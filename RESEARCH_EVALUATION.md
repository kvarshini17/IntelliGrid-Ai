# IntelliGrid AI — Research Evaluation (Phase 11)

This document summarizes the research framing, methodology, and actual
experiment results produced by `experiments/*.py`. All figures below were
generated by running the experiment scripts in this repository — none are
estimated, assumed, or back-filled. Re-run `python3 -m experiments.<name>`
to reproduce any number here exactly (fixed seeds are documented per
experiment).

## Research framing

**Working title:** *An Explainable, Knowledge-Grounded Decision Support
Framework for Energy Wastage Detection and Optimization in Smart
Buildings.* Not asserted as a final paper title — the actual contribution,
per the results below, is narrower and more specific than this framing
suggests (see "What the results actually support," at the end).

## Research questions and findings

### RQ1 — Can contextual rules identify potential energy-wastage conditions?

**Method:** Deterministic condition-based rules (Phase 2), evaluated two
ways: (a) applied to the real dataset, reporting condition-match counts;
(b) a controlled fault-injection correctness check on a synthetic copy.

**Real-dataset result:**

| Metric | Value |
|---|---|
| Total records | 1000 |
| Potential wastage records | 70 (7.0% of all records) |
| Potential wastage rate among unoccupied records | 71.43% |
| Potential HVAC wastage | 44 |
| Potential lighting wastage | 50 |
| Potential HVAC+lighting (combined) wastage | 24 |

**Fault-injection result:** Precision = Recall = 1.0 on the injected subset.
**This number is not a meaningful empirical finding and is reported as
such in the experiment's own output.** The detector is a deterministic
rule checking exactly the condition injected; perfect detection follows by
logical necessity, not empirical validation. What the injection *did*
usefully confirm: injecting synthetic faults into a copy left every
non-injected row's classification byte-identical to the real-dataset
baseline (verified programmatically) — i.e., the injection method is
clean and does not leak side effects.

**Answer to RQ1:** Yes, in the limited sense that the rules are correctly
and consistently applied — verified by construction, not discovered by
experiment. Whether these rule-identified conditions correspond to *real*
wastage cannot be assessed from this dataset (no ground truth exists), and
Phase 0's own audit found no consumption-magnitude signal supporting the
classic unoccupied+HVAC pattern. This is the central, unresolved
limitation of RQ1 as posed.

### RQ2 — Does context-aware anomaly detection identify unusual energy consumption better than a global baseline?

**Method:** 30 synthetic consumption spikes (2.0× multiplier, seed=456)
injected into a copy of the dataset; both the project's context-aware
detector (Phase 3) and a strawman global mean/std detector (implemented
only inside this experiment, not part of the project pipeline) were run
against the same injected ground truth.

**Result (this experiment is a genuine empirical comparison — the two
methods can and did disagree):**

| Metric | Context-Aware | Global Baseline |
|---|---|---|
| Recall | 0.60 | 1.00 |
| Precision | 0.643 | 1.00 |
| False Positive Rate | 1.03% | 0.00% |
| Coverage (can classify at all) | 887/1000 (88.7%) | 1000/1000 (100%) |

**The global baseline outperformed the context-aware method on this
specific injection design.** This runs counter to the naive expectation
that contextual conditioning should strictly improve detection, and is
reported honestly rather than reframed. Root-cause breakdown of the
context-aware method's 12 false negatives:

- **5 of 12** — the injected row fell in a context group below the minimum
  size (`MIN_CONTEXT_GROUP_SIZE=5`) and was structurally never classified
  (`INSUFFICIENT_BASELINE`).
- **7 of 12** — the row's context group had high residual natural variance
  in `energy_consumption`, which diluted the injected spike's z-score below
  the 2.0 threshold even though the same value would be a clear outlier
  globally.

The second cause is the more interesting finding: `energy_consumption`
correlates with `temperature` (r≈0.70, per the Phase 0 data-quality audit),
but **temperature is not part of the Phase 3 context key**. Context groups
therefore still mix records across a wide temperature range, inflating
within-group variance and making the context-conditioned z-score less
sensitive than a naive global one for *this* injection design. This is a
concrete, evidence-based direction for extending the context key (e.g.
temperature banding), not a flaw being hidden.

**Answer to RQ2:** Not supported by this experiment, as designed. Context
conditioning traded recall and coverage for a modest false-positive-rate
reduction, and the specific trade-off is explainable by an identified,
fixable gap in the context definition. A different injection design (e.g.
spikes correlated with the *context* dimensions already used, rather than
with temperature which isn't) might show the opposite result — this
experiment measures one injection design, not anomaly detection in general.

### RQ3 — Can deterministic optimization produce explainable energy-saving actions?

**Method:** Ran Phase 4 optimization across the full real dataset; checked
the hard occupied-room constraint empirically rather than just by code
inspection.

**Result:**

| Metric | Value |
|---|---|
| HVAC: KEEP / TURN_OFF | 956 / 44 |
| Lighting: KEEP / TURN_OFF | 950 / 50 |
| Mean ordinal score — KEEP | 0.0 |
| Mean ordinal score — TURN_OFF | −1.0 |
| TURN_OFF recommendations for occupied rooms | **0** (constraint holds on all 1000 records) |

Every `TURN_OFF` action carries a deterministic, traceable reason
(`"Room is unoccupied while {appliance} is active..."`); no action was
produced without a reason string, and the hard occupied-room constraint
was verified to hold on every single record, not assumed.

**Answer to RQ3:** Yes, within the scope actually implemented. Actions are
deterministic, constraint-respecting (verified), and explainable. No
kWh/cost savings are claimed — this dataset has no appliance-level
sub-metering to support one, stated directly in the experiment's own
output rather than omitted.

### RQ4 — Does RAG improve the grounding of AI-generated energy explanations?

**Method:** A 10-question, manually-labeled set (8 on-topic, 2 deliberately
off-topic), run against the actual retrieval pipeline.

**Result:**

| Metric | Value |
|---|---|
| Precision@1 (on-topic) | 0.75 |
| Precision@3 (on-topic) | 1.00 |
| Grounded response rate (on-topic) | 1.00 |
| Off-topic correctly reported "no evidence" | 1.00 (2/2) |

One of 8 on-topic questions retrieved a *plausible but not the intended*
top-1 document (the correct document appeared within the top 3). Both
off-topic questions ("capital of France," "chocolate cake recipe")
correctly triggered the "no relevant evidence" path rather than a
fabricated answer — this was verified, not assumed, and is the more
important property for research-integrity purposes (a RAG system that
never hallucinates on out-of-scope questions is more defensible than one
with marginally higher precision that sometimes does).

**Caveat stated directly in the experiment output:** retrieval uses a
TF-IDF (keyword-overlap) fallback, not a neural sentence embedding —
sentence-transformers requires a multi-GB PyTorch install not available in
this environment (see `rag/embeddings.py`). These numbers should not be
assumed to generalize to a neural-embedding configuration or a larger,
more semantically diverse corpus.

**Answer to RQ4:** Partially supported. Grounding (never answering without
retrieved evidence, correctly refusing off-topic questions) worked
perfectly in this small test set. Retrieval precision was good but not
perfect, and is tied to the specific (non-neural) embedding method used
here.

## What the results actually support

Scaled back from the working research framing to what the evidence here
actually shows:

1. **A clean separation between condition, wastage, and anomaly concepts
   is implementable and enforceable in code** (verified by dedicated tests
   showing all four wastage×anomaly combinations occur independently).
2. **Rule-based wastage detection is correctly and consistently applied**,
   but its real-world validity is unverifiable against this dataset.
3. **Context conditioning is not a strict improvement over a global
   baseline** for anomaly detection — it is a genuine trade-off whose
   outcome depends on whether the context key captures the variables that
   actually drive consumption variance (here, it does not capture
   temperature, and that gap is directly responsible for the weaker
   recall observed).
4. **Deterministic optimization can respect hard constraints reliably**
   and explain every decision, at the cost of not being able to quantify
   savings without richer (sub-metered) data.
5. **RAG grounding's most valuable property demonstrated here is refusal
   correctness** (never fabricating an answer when evidence is absent),
   more than retrieval precision, which is respectable but
   method-dependent.

## Limitations (consolidated)

- No ground-truth wastage or anomaly labels exist in the source dataset;
  no supervised accuracy/precision/recall/F1 is claimed against it.
- All fault-injection "ground truth" is synthetic and explicitly labeled as
  such everywhere it appears in code and output.
- The wastage fault-injection precision/recall of 1.0 is a correctness
  check, not an empirical result — stated explicitly to prevent
  misreading.
- The anomaly context-vs-global comparison used one specific injection
  design (uniform 2× multiplier); results may differ under a different
  injection design, especially one correlated with the existing context
  dimensions rather than with an excluded one (temperature).
- RAG evaluation used a 10-question, author-labeled set and a non-neural
  (TF-IDF) embedding method; not a large-scale or blind evaluation.
- Optimization scores are ordinal rankings, not kWh/cost estimates — no
  appliance-level sub-metering exists in this dataset.
- The knowledge base is project-authored general guidance, not verified
  primary-source citations (see `rag/knowledge_base.py`).

## Future work

- Extend the Phase 3 context key to include a temperature band, directly
  motivated by the RQ2 root-cause finding above, and re-run the global-vs-
  context comparison to see whether it changes the outcome.
- Run the anomaly fault-injection experiment with multiple injection
  designs (varying multiplier, varying which context dimensions correlate
  with the injected spike) rather than one fixed design, to characterize
  when context-conditioning helps versus hurts.
- If a disk/compute budget allows, re-run the RAG evaluation with a real
  sentence-transformers embedding model and compare precision@1/@3 against
  the TF-IDF baseline reported here.
- Expand the RAG evaluation question set beyond 10 manually-labeled
  questions for a more statistically meaningful precision estimate.
- If appliance-level sub-metering ever becomes available (real or more
  granular simulated data), revisit optimization scoring to use actual
  kWh/cost terms instead of ordinal rankings.
